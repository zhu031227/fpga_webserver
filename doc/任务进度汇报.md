## 三、完成详情与技术要点

### 1. 理解 18 拍时序图

模式 0 顺序查找引擎（`rtl/mac_whitelist_seq.v`，`ENTRY_NUM=16`）每笔查表固定 **18 拍** 完成判定，L1 仿真 T7 用例实测 `cyc=18` 且断言通过。

要点：
- 帧 SOP 沿触发 `lookup_req` 启动查表，18 拍内完成 IDLE → 逐槽顺序比较 → 命中/未命中输出的完整节奏；
- `lookup_done` / `lookup_match` / `lookup_busy` 与帧数据流的对齐关系：busy 期间数据帧在数据通路上等待，判定结果门控放行/丢弃；
- 18 拍节拍覆盖全表 max=16 槽扫描 + 首尾拍开销的排布。

### 2. 吃透 FSM 逻辑

吃透引擎状态机（IDLE → 查找 → 输出）：
- miss 时按地址递增逐槽遍历，直至扫描完所有槽位后输出 miss；
- 命中即提前退出，不再继续扫描后续槽位；
- **DEL 语义**：表项 `bit31` 置位即删除，查找时跳过已删槽位（L1 T5 用例验证表满 `free_idx=0xF` 场景）；
- 状态转移与 18 拍节拍的对应关系，以及 `whitelist_en` / `default_pass` 在门控端的综合作用。

### 3. 理解影子寄存器 + BRAM 双副本

配置通路与查表读操作解耦：
- CPU 侧经 LCPU 总线写**影子寄存器（shadow）**，硬件查表读 **BRAM 双副本**；
- 双缓冲机制避免「CPU 写表」与「硬件读表」的读写冲突，配置写后整体切换副本生效；
- 仿真要点：iverilog 下未初始化 BRAM 读回为 X，tb 需对全表做 DEL 初始化后 miss 语义才确定（见《项目状态.md》关键记录）。

### 4. 理解 cfg_* 配置译码

理解配置寄存器到引擎的译码通路（`cfg_clk` / `cfg_reset_l` / `cfg_rlwh`（1=写 0=读） / `cfg_addr[11:0]` / `cfg_wdata[31:0]` / `cfg_rdata[31:0]`）：
- 表项写入按 `cfg_addr` 译码到槽位地址，`cfg_wdata` 携带 MAC + 有效/DEL 标志；
- 配置读回 `cfg_rdata` 组合译码，供管理面回读表项；
- 明确 DEL+bit31 删除编码在译码侧的落位。

### 5. 理解 cpu_channel_tri 门控逻辑

数据通路 **eth1 → eth2** 的白名单门控：
- 从帧中提取 **SrcMAC** → 触发查表 → 查找结果决定该帧是否 push 到 eth2；
- **2026-08-30 修复的缺陷**：`mac1_byte_cnt` 在 SOP 拍被增量赋值覆盖，导致非首帧源 MAC 偏移 1 字节；修复为 SOP 置 1 + `else if`；
- push 门控与丢弃计数（0x21 drop）联动，命中放行、未命中丢弃（`default_pass` 决定默认策略）。
