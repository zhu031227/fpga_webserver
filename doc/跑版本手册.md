## 0. 快速通道（树是绿的、环境是现成的，按序敲这 8 条）

```bash
cd /home/haitaoz/work/FPGA_Prj/fpga_webserver-wldev-v2

# ① 前置：共享库正本（未跟踪的本地文件，快照同步可能丢）
cp local/define.sv ../ip_common/rtl/

# ② L1 单元仿真（G2）
iverilog -g2012 -s tb_mac_whitelist_seq -o /tmp/tb_seq.vvp -I sim \
    sim/define.sv sim/tb_mac_whitelist_seq.sv \
    rtl/mac_whitelist_seq.v \
    ../ip_common/rtl/dual_clock_simple_dual_port_ram.v && vvp /tmp/tb_seq.vvp
#    期望: ALL 8 TESTS PASSED（含 [PASS] T7 cyc=18）

# ③ L2 集成仿真（G3）
iverilog -g2012 -s tb_wl_integration -o /tmp/tb_wl.vvp -I sim \
    sim/define.sv sim/tb_wl_integration.sv \
    rtl/cpu_channel_tri.v rtl/mac_whitelist_seq.v \
    ../ip_common/rtl/ram2pktfifo_int.v ../ip_common/rtl/package_fifo_v2.v \
    ../ip_common/rtl/pktfifo2ram_int_v2.v ../ip_common/rtl/sop_eop_gen.v \
    ../ip_common/rtl/dual_clock_simple_dual_port_ram.v \
    ../ip_common/rtl/single_clock_simple_dual_port_ram.v \
    ../ip_common/rtl/single_clock_fifo.v \
    ../ip_common/rtl/dual_clock_fifo.v \
    ../ip_common/rtl/pulse_clock_region_pass.v && vvp /tmp/tb_wl.vvp
#    期望: 7 用例全 PASS（含 case600 CLEAR 期间查找）
#    报 undefined module 就按报错从 ../ip_common/rtl/ 逐个补

# ④ 编译固件（生成 tcl/InstructRAM.tcl 固定名）
cd c_build && make PLATFORM=xilinx riscv_reset_addr=0xf TCL_BASE=0x8000 && cd ..

# ⑤ 构建 bitstream（G4，20~60 分钟）
cd build_xilinx_xc7a35tfgg484 && ./build_fpga.sh NNNN && cd ..     # NNNN=版本号，自增
#    产物: webserver_xilinx_xc7a35tfgg484_vNNNN_<时间戳>/同名.bit

# ⑥ 烧 bit（SRAM 易失，断电即失；openFPGALoader 禁用——对本板误读 IDCODE）
vivado -mode batch -source scripts/program_bit_vivado.tcl -tclargs \
    webserver_xilinx_xc7a35tfgg484_vNNNN_<时间戳>/webserver_xilinx_xc7a35tfgg484_vNNNN_<时间戳>.bit

# ⑦ 加载固件（JTAG-AXI 写片内指令 RAM，3~5 分钟，bit 无需重烧）
vivado -mode batch -source scripts/load_firmware_vivado.tcl

# ⑧ 连通 + 板测（G5）
ping -c2 -I wlp4s0 192.168.1.128
curl -s --interface wlp4s0 http://192.168.1.128/api/wl/status
```

`vivado` 不在 PATH 时用全路径：`/home/haitaoz/Xilinx/2024.1/Vivado/2024.1/bin/vivado`

## 2. 板测 5 项（G5，★最后一道门禁）

**板测纪律**：请求间隔 **≥2 秒**（密集请求必得空响应）；每次 POST 后必须 GET 读回确认实际生效；JSON 一律 `python3 -m json.tool` 校验。所有 curl 带 `--interface wlp4s0`。

| # | 项目       | 操作                                                                                                                    | 通过标准                               |
| - | ---------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| 1 | 管理面回读 | 网页`http://192.168.1.128/wlconfig` add 一条 MAC → `curl -s --interface wlp4s0 http://192.168.1.128/api/wl/hwlist` | 软件表与硬件表两视图一致               |
| 2 | 加白放行   | 加 PC**数据口** MAC → enable → 数据口打流/ping 穿桥                                                             | 通；`jflow.tcl` 看 e2_tx(0x11A) 增长 |
| 3 | 删白拦截   | 删该 MAC（defpass=0）→ 再打流                                                                                          | 不通；drop(0x21) 增长、e2_tx 零增长    |
| 4 | 全放模式   | en=0 + defpass=1                                                                                                        | 任意 MAC 都通                          |
| 5 | 持久化     | `curl -s --interface wlp4s0 -X POST http://192.168.1.128/api/wl/save` → 复位/重载固件 → 读回                        | 列表与开关状态从 Flash 恢复            |

数据通路计数器一键读取（eth1→eth2 白名单链路的铁证）：

```bash
vivado -mode batch -source scripts/jtag/jflow.tcl
# 输出: e1_rx(0x110) e1_tx(0x112) e2_rx(0x118) e2_tx(0x11A) drop(0x21) wl_ctrl(0x300)
```

> 注意：白名单过滤的是 **eth1→eth2 数据通路的 SrcMAC**。ping 必须**穿桥**（PC→板→对端），
> ping 板子管理口 IP 与白名单无关。管理面走 WiFi 有 AP 单播真空窗（10~45s/约 90s 周期）：
> 空响应/超时先重试，别急着查板；裁决实验=管理口改有线。

## 3. 排障三板斧（JTAG 寄存器）

```bash
vivado -mode batch -source scripts/jtag/jr.tcl        # 单寄存器读（用法见脚本头）
vivado -mode batch -source scripts/jtag/jpoll.tcl     # 活性+计数轮询
```

| 读哪里                           | 判据                                                                 |
| -------------------------------- | -------------------------------------------------------------------- |
| `0x07` 读两次                  | 在走 = CPU 活；冻结 = CPU 假死（v0009 固件起 0x06 会被写，判据有效） |
| `0x12` 引导阶段                | 0x10 进入 / 0x11 读 Flash / 0x12 加载 OK / 0x13 失败走默认           |
| `0x300` / `0x21` / `0x11A` | wl_ctrl 真值（bit0=en, bit1=defpass）/ 丢弃计数 / 转发计数           |
| `0x301`                        | wl_status：{used_cnt, LOOKUP_MODE}（加条目 0x100、删回 0x0）         |

**假死恢复**：CPU 假死/行为异常 → 重跑 `load_firmware_vivado.tcl` 即可（bit 不用重烧）。
**掉电恢复**：bit 是 SRAM 易失 → 重烧 bit + 重载固件；save 过的配置从 Flash 自动恢复。

## 4. 常见坑速查（每次都栽过的才配进表）

| 症状                                                | 根因                                                 | 处置                                                                                                                   |
| --------------------------------------------------- | ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| build 报 define.sv 不存在（filelist.cfg:47）        | 共享库快照丢了未跟踪的`../ip_common/rtl/define.sv` | `cp local/define.sv ../ip_common/rtl/`                                                                               |
| 加载了旧固件，板行为与代码对不上                    | 拿了`tcl/` 下带时间戳的历史副本                    | **永远用固定名 `tcl/InstructRAM.tcl`**（每次 make 重新生成）；走 `scripts/load_firmware_vivado.tcl` 自动定位 |
| vvp 秒退（299ns）                                   | 共享库内嵌自测 tb 被当顶层                           | iverilog 命令必须带`-s <tb名>`                                                                                       |
| curl 空响应/超时                                    | AP WiFi 单播真空窗（环境，非板卡）                   | 间隔≥2s 重试；ping 同步死=真空窗实锤                                                                                  |
| `git status` 里 `c/inc/build_time.h` 常年 dirty | 自动生成的时间戳噪声                                 | **永不提交**                                                                                                     |
| 烧录 IDCODE 报错                                    | 用了 openFPGALoader                                  | 本板禁用，统一 Vivado Hardware Manager                                                                                 |
| 时序报告出现违例                                    | v0011 起应为零违例                                   | 任何违例都是新问题，查路径别忽略                                                                                       |
| 多会话并行改文件打架                                | 历史踩坑                                             | 动文件前先确认没有别的会话在改                                                                                         |
