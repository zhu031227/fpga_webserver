# 日报 · 2026-09-03 —— HAST（布谷鸟哈希）白名单表设计细节

## 今日目标

专门梳理 **模式 2（布谷鸟哈希 / cuckoo hash）白名单查找引擎** 的表设计细节：把「CPU 如何往表里**添加 / 删除 / 修改**」的基本原理讲透，并贴清 RTL 与 C 固件的具体实现，作为后续维护与交接的权威参考。同步记录今天的运行时「切换查找模式」新特性。

## 一、设计总览

| 项 | 值 |
|---|---|
| 存储 | 2 个 BRAM bank（bank0 按 h0、bank1 按 h1），各 64 行 × 49 bit（1 valid + 48 MAC） |
| 物理槽 | 128 个，槽号编码 `slot[6:0] = {bank, row[5:0]}`（0~63 = bank0，64~127 = bank1） |
| 设计容量 | 96 条（负载 75%）；但布谷鸟 d=2 负载阈值 ≈50%，随机 MAC 实测到 ~88 就 8 跳回滚（顺序 MAC 因退化哈希能满 96，见 §二） |
| 查找 | **2 拍** @125MHz = 16ns，与表条数无关（招牌卖点） |
| 哈希 | fold6（48bit 切 8 段 6bit 全 XOR）；`h0(mac)=fold6(mac)`、`h1(mac)=fold6(byteswap48(mac))` |
| 插入 | **软件执行**（C 固件），含有界 eviction（≤8 跳）+ 失败快照回滚 |
| 双副本 | 主 BRAM（查表用）+ shadow_rf 寄存器堆（CPU 读回用）+ valid_bits（popcount 用），三条写路径同拍同步 |
| 配置口 | SubBus 0x5000，经 reg_webserver → ramintf → cfg 口（50MHz，电平敏感、无握手） |

核心分工：**哈希计算与 eviction 搬移全部放软件（C）**，硬件只做「查」（2 拍并行读两个 bank）+「存」（cfg 口写 BRAM/shadow/valid_bits）。硬件信任软件维护的 INV 不变式，自己从不重算哈希验证。

## 二、硬件存储结构与哈希

### 2.1 三个存储副本（必须同拍一致）

```verilog
// mac_whitelist_cuckoo.v
reg  [48:0] shadow_rf [0:SLOTS-1];   // 128 深寄存器堆：cfg_clk 写，组合读（CPU 读回 0x06/07/08）
reg  [SLOTS-1:0] valid_bits;         // 128 位有效位：驱动 used_cnt popcount
// 两个 BRAM bank（dual_clock_simple_dual_port_ram, 49bit）
```

每条「写」动作（`WR` 命令）在**同一个 cfg_clk 拍**写三处：
```verilog
4'h3: begin  // WR — 写 {1'b1, cfg_mac} 到 cfg_idx 槽的双存储
    bram_wr_en_r        <= 1'b1;
    bram_wr_addr_r      <= cfg_idx;
    bram_wr_data_r      <= {1'b1, cfg_mac};
    sh_wr_en_r          <= 1'b1;
    sh_wr_addr_r        <= cfg_idx;
    sh_wr_data_r        <= {1'b1, cfg_mac};
    valid_bits[cfg_idx] <= 1'b1;
end
```

### 2.2 哈希函数（C 与 RTL 必须逐位一致，各写一份）

```c
// c/whitelist.c
#define WL_SLOT(bank,row)  ((uint8_t)(((bank)<<6)|(row)))

static uint8_t wl_fold_u64(uint64_t x) {   // 48bit 切 8 段 6bit，全 XOR
    return (uint8_t)((x & 0x3FULL) ^ ((x>>6)&0x3FULL) ^ ((x>>12)&0x3FULL)
                   ^ ((x>>18)&0x3FULL) ^ ((x>>24)&0x3FULL) ^ ((x>>30)&0x3FULL)
                   ^ ((x>>36)&0x3FULL) ^ ((x>>42)&0x3FULL));
}
static uint64_t wl_mac_u64(const uint8_t mac[6]) {
    return ((uint64_t)mac[0]<<40)|((uint64_t)mac[1]<<32)|((uint64_t)mac[2]<<24)
         | ((uint64_t)mac[3]<<16)|((uint64_t)mac[4]<<8)|(uint64_t)mac[5];
}
static uint64_t wl_bswap48(uint64_t x) { /* 6 字节反转 */ }
static uint8_t wl_h0(const uint8_t mac[6]) { return wl_fold_u64(wl_mac_u64(mac)); }
static uint8_t wl_h1(const uint8_t mac[6]) { return wl_fold_u64(wl_bswap48(wl_mac_u64(mac))); }
```

> ⚠️ **退化哈希坑**：形如 `02:00:00:00:00:XX` 的**顺序 MAC**，`byteswap` 后字节对称，fold6 是对称 XOR → **`h0 == h1`**。这类 MAC 每个 `(h0,h1)` 类恰 2 条，能确定性灌满 96；而**随机 MAC**（h0≠h1）是正常布谷鸟，~88 条就因「同 (h0,h1) 类第 3 成员必 8 跳失败」卡住。二者不矛盾，勿误判。

## 三、寄存器表（SubBus 基址 0x5000，偏移 0x00~0x0B）

| 偏移 | 名称 | 模式 2 语义 |
|---|---|---|
| 0x00 | INDEX | RW `[6:0]`=槽号 `{bank,row}`；**`[31]=1` 附带删除该槽** |
| 0x01/0x02 | MAC_H / MAC_L | RW 暂存 `cfg_mac[47:16]` / `[15:0]` |
| 0x03 | WR | WC 把 `{1'b1, cfg_mac}` 写入 `cfg_idx` 槽（BRAM+shadow+valid 三写） |
| 0x04 | DEL | WC 把 `49'b0` 写入 `cfg_idx` 槽 |
| 0x05 | CLEAR | WC 启动 128 拍序列器扫清全部物理槽 |
| 0x06/07/08 | RD_MAC_H/L / RD_VALID | RO 读 `shadow_rf[cfg_idx]`（组合读，零延迟） |
| 0x09 | FREE_IDX | 哈希模式无「线性空闲」概念，恒 0x7F 占位（C 不用） |
| 0x0A | MAX_ENTRIES | RO 恒 96（C 判满依据） |
| 0x0B | USED_CNT | RO popcount(valid_bits) 0~128 |

写入幂等（rlwh 电平持续约 3 拍，同一笔写被译码多次但内容恒定 → 重复无害）；读组合零延迟。

## 四、软件契约（正确性根基）

- **INV-A**：每条有效条目必落在 `{0,h0(mac)}` 或 `{1,h1(mac)}` 两个候选槽之一。
- **INV-B**：槽 `{bank,row}` 里的条目，其 `h_bank(mac)==row`（槽号就是它自己的哈希位）。
- **INV-C**：一次插入/删除事务期间（≤8 跳 × 4 笔写 ≈ 数十 µs），个别查找可瞬时 miss；事务外全命中。本设计接受该瞬时窗口。

RTL 从不重算哈希验证 INV-B——那是 C 的责任 + tb 的 INV-B 裁判。

## 五、CPU 如何「添加」（核心：`wl_add_mode2`）

添加走 6 步，**每步都保证 INV-A/B**，任意退出路径全表 INV 不破：

1. **全零拒绝**：全零 MAC 禁止入表（否则与 49'b0 无效条目混淆）。
2. **判满**：`sw_wl_count >= WL_CAP(96)` 直接返回 `-2`（表满）。
3. **查重幂等**：新 MAC 已在 s0 或 s1 → 返回原槽，**不占新槽、count 不涨**。
4. **空位直达**：s0/s1 任一空 → 直接写入（优先 s0），不踢人。这是**最常见的路径**（表未满时多数添加走这里）。
5. **有界 eviction**：双槽皆占才踢人。先存**全表快照**（回滚用），然后 `cur=新MAC, bank=0`，最多 8 跳：
   - 每跳算 `cur_tgt = {bank, h_bank(cur)}`（cur 在 bank 侧的哈希槽）；
   - 空 → cur 入住，完成；
   - 占 → **先存受害者再覆盖**，`cur=受害者, bank=1-bank`（交替 bank 防乒乓：被 bank b 踢出的受害者，唯一没试过的是 bank 1-b 侧）。
6. **8 跳失败 → 快照回滚**：`CLEAR` 全表 → 按快照原槽逐条直接写回（必然无冲突）→ 返回 `-1`（回滚，非真满）。

失败码区分（2026-09-03 起）：`-1`=8跳回滚、`-2`=判满、`-3`=全零，web 层分别报 `collision` / `table full` / `invalid MAC`。

```c
// c/whitelist.c（节选，完整见文件）
static int wl_add_mode2(uint8_t mac[6]) {
    uint8_t s0 = WL_SLOT(0, wl_h0(mac));
    uint8_t s1 = WL_SLOT(1, wl_h1(mac));
    uint8_t cur[6], victim[6], tgt;
    uint8_t saved_cnt = 0, i;
    int bank, hop, placed;

    if (wl_is_zero_mac(mac)) return -3;
    if (sw_wl_count >= WL_CAP) return -2;
    if (sw_wl_valid[s0] && !memcmp(sw_wl_mac[s0], mac, 6)) return s0;  // 查重
    if (sw_wl_valid[s1] && !memcmp(sw_wl_mac[s1], mac, 6)) return s1;

    if (!sw_wl_valid[s0] || !sw_wl_valid[s1]) {            // 空位直达
        tgt = sw_wl_valid[s0] ? s1 : s0;
        wl_hw_write_entry(tgt, mac);
        sw_wl_valid[tgt] = 1; memcpy(sw_wl_mac[tgt], mac, 6);
        sw_wl_count++; return tgt;
    }

    for (i = 0; i < WL_SLOTS; i++)                         // 全表快照
        if (sw_wl_valid[i]) { wl_saved_slot[saved_cnt]=i;
            memcpy(wl_saved_mac[saved_cnt], sw_wl_mac[i], 6); saved_cnt++; }

    memcpy(cur, mac, 6); bank = 0; placed = 0;
    for (hop = 0; hop < WL_MAX_EVICT && !placed; hop++) { // 有界 eviction
        uint8_t cur_tgt = (bank==0) ? WL_SLOT(0, wl_h0(cur)) : WL_SLOT(1, wl_h1(cur));
        if (!sw_wl_valid[cur_tgt]) {                      // 找到空位 → 完成
            wl_hw_write_entry(cur_tgt, cur);
            sw_wl_valid[cur_tgt] = 1; memcpy(sw_wl_mac[cur_tgt], cur, 6);
            sw_wl_count++; placed = 1;
        } else {                                          // 踢人（先存受害者再覆盖）
            memcpy(victim, sw_wl_mac[cur_tgt], 6);
            wl_hw_write_entry(cur_tgt, cur);
            memcpy(sw_wl_mac[cur_tgt], cur, 6);
            memcpy(cur, victim, 6);
            bank = 1 - bank;
        }
    }
    if (!placed) {                                        // 8 跳失败 → 回滚
        wl_hw_clear_all_and_wait();
        memset(sw_wl_valid, 0, sizeof(sw_wl_valid)); sw_wl_count = 0;
        for (i = 0; i < saved_cnt; i++) {
            wl_hw_write_entry(wl_saved_slot[i], wl_saved_mac[i]);
            sw_wl_valid[wl_saved_slot[i]] = 1;
            memcpy(sw_wl_mac[wl_saved_slot[i]], wl_saved_mac[i], 6);
            sw_wl_count++;
        }
        return -1;
    }
    return tgt;
}
```

**不变式证明**：空位直达/eviction 找到空位 → `count` 与 `valid` 同时 +1；eviction 踢人只改槽不增减条目；回滚重置后按 `saved_cnt` 逐条重建。故 `sw_wl_count == popcount(sw_wl_valid)` 恒成立（已穷举全分支验证）。

## 六、CPU 如何「删除」（`whitelist_delete`）

模式 2 删除是**单槽删除**（不是按 MAC 找槽——槽号由影子表给出）：

```c
// c/whitelist.c（mode2 分支）
if (wl_is_mode2()) {
    if (index >= WL_SLOTS || !sw_wl_valid[index]) return -1;
    wl_hw_delete_entry(index);              // INDEX|bit31 一笔带删
    sw_wl_valid[index] = 0;
    memset(sw_wl_mac[index], 0, 6);
    if (sw_wl_count > 0) sw_wl_count--;
    return 0;
}

static void wl_hw_delete_entry(uint8_t slot) {
    subbus_write(WL_SUBBUS_ADDR, WL_REG_ENTRY_INDEX, 0x80000000u | (uint32_t)slot);
}
```

RTL 侧 `INDEX` 写带 `[31]=1` 时，同拍执行删除（写 49'b0 到双存储 + 清 valid）：
```verilog
4'h0: begin
    cfg_idx <= cfg_wdata[6:0];
    if (cfg_wdata[31]) begin
        bram_wr_en_r <= 1'b1; bram_wr_addr_r <= cfg_wdata[6:0]; bram_wr_data_r <= 49'b0;
        sh_wr_en_r   <= 1'b1; sh_wr_addr_r   <= cfg_wdata[6:0]; sh_wr_data_r   <= 49'b0;
        valid_bits[cfg_wdata[6:0]] <= 1'b0;
    end
end
```

删除后 hash 布局仍满足 INV-A/B（删掉一条，其余条目仍在自己的哈希槽，无需重排）。

## 七、CPU 如何「修改」

**表内没有「原地修改」**——每条目是「固定 48bit MAC + 1 valid」，MAC 一变哈希槽就变，无法原地改。所以「修改一条 MAC」= **删除旧槽 + 添加新 MAC** 两步：

```
旧 MAC A → 新 MAC B：
  1) 查 A 的槽号（影子表 sw_wl_mac 反查，或 hwlist 枚举）
  2) whitelist_delete(A 的槽号)    // 删除
  3) whitelist_add(B)              // 添加（哈希重新落位，槽号可能完全不同）
```

「修改」全局配置则走 `wl_ctrl`（0x300）寄存器位，不涉表条目：

| 位 | 含义 |
|---|---|
| `[0]` | 白名单使能（enable） |
| `[1]` | 默认策略（default_pass：禁用时 0=全断 / 1=全放） |
| `[2]` | 查找模式（1=布谷鸟 / 0=顺序，2026-09-03 新增，见 §九） |

## 八、配置通路（CPU ↔ 硬件握手原理）

CPU 一次「写一笔寄存器」的完整链路：

```
LCPU_REG32_WRITE(0x80000000 + 0x5000+offset 字地址)
  → riscv32intfbridge（PicoRV32 mem_valid→req 单拍脉冲，rhwl=0 写）
  → reg_webserver（译码 0x5000~0x5FFF → SUBBUS_mac_whitelist_Req）
  → ramintf（3 拍延迟：Ram_RlWh 单拍脉冲、Ram_Addr 保持、ack=req_d[2]）
  → mac_whitelist_cuckoo cfg 口（cfg_clk=50MHz 电平敏感写）
```

关键纪律（写在 C 里）：
```c
// 每笔写后必须 flush（读 0x500A），确保上一笔已提交
static inline void subbus_write(uint16_t base, uint16_t off, uint32_t data) {
    LCPU_REG32_WRITE(base + off, data);
    volatile uint32_t dummy = LCPU_REG32_READ(base + WL_REG_MAX_ENTRIES); // flush
    (void)dummy;
}
```

**为何安全**：reg_webserver.clk 与 cfg_clk 同为 clk_50mhz（无 CDC），`cfg_idx` 在事务 ack 前 1 拍已锁存 → 写 INDEX 后紧跟的 WR 一定用的是已锁存的槽号，无竞态。

## 九、运行时切换查找模式（seq ↔ cuckoo，今日新增）

原 `LOOKUP_MODE` 是**综合期 generate 二选一**，切模式须重出 bit。今日改为**双引擎常驻 + 运行时 mux**：

- `mac_whitelist_top.v` 同时实例化 `mac_whitelist_seq`(模式0) + `mac_whitelist_cuckoo`(模式2)，`lookup_mode_sel`（=`wl_ctrl[2]`）mux `lookup_match/done/busy`、`cfg_rdata`、`wl_status`。
- cfg 写口**广播两引擎**（写幂等、CLEAR 同清两引擎）；读口按活跃引擎 mux。
- 固件 `whitelist_set_mode()`：清两引擎表 + 写 `wl_ctrl[2]` + 重置 sw 镜像。**硬切换**（切模式清空白名单）。
- 复位默认 `wl_ctrl=3'b100`（布谷鸟）；`whitelist_apply_snapshot` 只恢复 `[1:0]` 保留 `[2]`（今日修的坑）。

## 十、上板实测记录（可复现，含命令与实测数据）

### 10.0 环境与判据

- 板：ACX750 xc7a35t；固件 IP `192.168.1.128`；PC 管理面 `wlp4s0`(192.168.1.10/24)；PC MAC `b4:8c:9d:32:47:b1`。
- **curl 必须 `--noproxy '*'`**（本机 http_proxy 会劫持内网 → 假超时 code 000）。
- 三计数判据（`GET /api/wl/dbg`）：`used`=固件 `sw_wl_count`、`vpop`=popcount(sw_wl_valid)、`hwused`=硬件 0x500B popcount(valid_bits)。三者恒等即软硬件一致。
- 寄存器：`0x301` wl_status([7:0]=mode)、`0x500B` USED_CNT popcount、`0x30` LED 心跳（1.1s 两次采样变=cpu_alive）、`0x12` boot 阶段。

### 10.1 灌表容量实测（布谷鸟 d=2 的硬边界）

| MAC 族 | 结果 | 根因 |
|---|---|---|
| 顺序 `02:00:00:00:00:XX` | **96/96 确定性灌满** | 退化哈希 `h0==h1`（byteswap 字节对称 + fold6 对称 XOR），每个 (h0,h1) 类恰 2 条 |
| 随机 `02:XX:XX:XX:XX:XX` | **88/96**（7 条 8 跳回滚 + 1 条瞬时 invalid MAC） | 正常布谷鸟 d=2 负载阈值 ≈50%，~88 条即「同 (h0,h1) 类第 3 成员必 8 跳失败」 |

命令（灌 96 条顺序 MAC + 查三计数）：
```bash
for i in $(seq 0 95); do
  mac=$(printf "02:00:00:00:00:%02X" $i)
  curl --noproxy '*' -s -X POST 192.168.1.128/api/wl/add --data "{\"mac\":\"$mac\"}"
done
curl --noproxy '*' -s 192.168.1.128/api/wl/dbg   # {"used":96,"hwused":96,"vpop":96,...}
```
回滚失败的都返回 `collision`（不是 `table full`，二者已区分）；回滚前后三计数一致、逐条可查。

### 10.2 步骤 9.3 功能回归（5 项全过）

| # | 项 | 实测 |
|---|---|---|
| 1 | 模式号上报 | `/api/wl/status` → mode=2 |

### 10.3 步骤 10.1 并发验证（INV-C 窗口实测）

- 条件：enable=1 + PC MAC 白名单，灌到 90 条，`ping -i 0.2` 持续打，快速增删 10 次 random MAC。
- **结果**：ping **6/6 收到 0% 丢包**；增删后 `used==hwused==vpop==90` 一致、无条目丢失。
- 结论：eviction 瞬时窗口（≤32µs）对正常流量无感，INV-A/B 未破坏。

### 10.4 步骤 10.2 掉电恢复（CPU 复位模拟，clear-race 修复验证）

- 加 5 条（PC MAC + 4 顺序）→ `POST /api/wl/save` 落 flash → `scripts/reset_cpu.tcl`（`jwrite 0xF 0x0`→`0x1` 仅复位 CPU 不重载固件）。
- **结果**：`status used=5`、`dbg used==hwused==vpop==5` 三者一致、`list` 5 条齐全、ping 5/5 0% 丢包（PC MAC 过滤正确）。
- 关键：**clear-race 修复确认生效**——boot 快照恢复时 `whitelist_clear_all` 等满 128 拍序列器，头几条未被抹。物理断电那一步需固件先烧 flash（当前 JTAG 载入，见 §遗留）。

### 10.5 步骤 10.3 性能实测（满/空表同速 = O(1)）

| 表状态 | ping RTT min / avg |
|---|---|
| 空表（1 条） | 2.295 ms / 9.862 ms |
| **满表（96 条）** | 2.231 ms / 6.921 ms |

满表与空表延迟一致（min 都 ~2.3ms）→ **查找延迟与条数无关（2 拍 O(1)）**。精确 2 拍(16ns)被 ~ms 软件/网络延迟淹没，由 RTL 状态机结构 + 仿真 `==2` 断言保证。

### 10.6 运行时「切换查找模式」实测（今日新特性）

- **默认**：重配后 mode=2（布谷鸟），`max=96`。
- **往返**：`POST /api/wl/mode {"mode":"0"}` → `max=16`；`{"mode":"2"}` → `max=96`。
- **读回 mux 实测**：同一 MAC `02:00:00:00:00:01`，布谷鸟模式落**哈希槽 33**（h0 正确），顺序模式落**槽 0**（顺序）。`hwlist` 的 `used(0x500B)` 与 `max` 均随模式正确切换——证明 cfg 读口按活跃引擎 mux。
- 注意：切模式是**硬切换**（清空白名单条目）。

### 10.7 幽灵计数排查（最终定性）

- 之前「96→90 幽灵计数」经 6 路并行 + 对抗复核**全排除固件内存越界写**（TCP 数组有界、栈 33KB、add 逻辑 count==popcount 恒成立、写路径 cfg_idx 在 ack 前锁存、bss 清零、canary）。timing 零违例。
- 最终定性：**是 wlp4s0 单播真空窗(~90s 周期)的偶发网络丢响应**，非固件 bug；固件 `used==hwused==vpop` 恒一致（逐条追踪 96/96）。

## 遗留与注意

- **布谷鸟 d=2 灌不满 96**（随机 MAC 实测 ~88 就回滚）：设计容量问题，文档 R04 已改步骤 9.3-3 判据为「灌到首次回滚、三计数一致」；真 96 需 d=3 或更强哈希，待与作者确认。
- **桥接过滤端到端验证未做**：白名单过滤的是 eth1(LAN)→eth2 桥接转发（`cpu_channel_tri` 里 `eth1_fwd_wpkt_push = ... && (wl_result_match || ...)`），ping 走 CPU 管理面不经 bridge，故 ping 测不出过滤切换；需 eth1 挂设备打流验证。
- canary `wl_gpre/wl_gpost` 在 `.data` 不守 `.bss` 的 sw 数组，守卫诊断无效（勿再据此判断）。
- 物理断电持久化需先把固件烧 flash（当前 JTAG 载入，断电即失）。
