## 2026-09-04 —— 模式 2 布谷鸟哈希引擎：RTL 设计完成，L1/L2 两级仿真通过

> 开发流程按既定七环节推进：**契约 → 骨架（双 bank）→ 哈希+查找 → 辅助/集成改动 → TB 搭建 → L1 仿真+回归 → L2 集成仿真**，全部闭环。

### 1. 契约

接口与模式 0 引擎完全同构（lookup_req/match/done/busy + cfg RAMIF 配置口 + wl_used_cnt 观测口），上层集成零改动成本；寄存器表 0x0~0xB 语义定稿，槽位号由 4 位扩展为 7 位 `{bank, row[5:0]}`；三条软件契约定稿：INV-A（每条目必居其双哈希槽之一）、INV-B（槽位号=自身哈希位）、INV-C（插入/删除事务窗口内允许瞬态 miss，窗口外全命中）；容量定档 2 bank × 64 行 = 128 物理槽，设计容量 CAPACITY=96（75% 负载，超出后 eviction 失败率上升）。

### 2. 骨架（双 bank）

`mac_whitelist_cuckoo.v` 骨架搭建：双 bank BRAM 例化（`dual_clock_simple_dual_port_ram` ×2，A 口 cfg_clk 写 / B 口 clk 125M 读）；128 深 shadow 寄存器堆（cfg_clk 写、组合读，CPU 回读 0 拍延迟）；valid_bits（128 位）+ used_cnt 组合 popcount 链；CLEAR 序列器（7 位计数器 128 拍扫全双 bank，期间写口由序列器独占）。

### 3. 哈希 + 查找

- 哈希：`fold6` = 48bit 按 8×6bit 分块异或折叠；h0 = fold6(mac)，h1 = fold6(字节序反转(mac))——RTL / C 固件 / TB 三方逐位一致，单一真源在 C `wl_fold`；
- 查找 FSM 两态两拍：req 拍哈希组合直驱双 bank 读地址，次拍 49 位 {valid,MAC} 并行比较锁存——**固定 2 拍 @125MHz = 16ns**，与表占用无关；
- 实现要点：读地址由 `lookup_req` 直接驱动、不参与 state 门控——规避综合与仿真在采样沿的事件序差异导致地址塌陷（对齐 seq 引擎 DONE 判决的既有处理方式）。

### 4. 辅助 / 集成改动

- `mac_whitelist_top`：由综合期参数二选一改为**双引擎常驻 + 运行时 mux**（`wl_ctrl[2]` 经 CDC 同步选择，网页运行时可切，免重出 bit）；cfg 写口同拍广播双引擎，读口/查找结果/wl_status 按活跃引擎选择；
- `webserver_wrapper`：wl_ctrl CDC 位宽 2→3，wl_status 聚合 `{used_cnt, 运行时模式号}`；
- C 固件：哈希插入（双槽落位 + ≤8 跳交替 bank 驱逐 + 受害者先存后覆 + 失败按快照回滚）、按槽删除、查重、运行时模式判别（wl_is_mode2）。

### 5. TB 搭建

`sim/tb_mac_whitelist_cuckoo.sv`（14 用例矩阵）：写读删清基本语义、灌满判满（第 97 条拒收 + MAX/FREE 语义）、定向冲突构造触发 eviction（p/q/x 配方 hops=2、g/t/w/v/s/x 链 hops=4）、空表查找、槽违例注入（INV-B 可诊断性）、同 MAC 查重；内置 tb 侧哈希副本 + DUT↔镜像双裁判 + 无序集合金模型，对拍含命中与 miss 双侧样本。

### 6. L1 仿真 + 回归

- **14/14 全 PASS**：T7 周期数强断言 `cyc==2`（三模式分水岭）；T9/T10 定向 eviction 链全命中且 hops 计数正确；T11 金模型 **500 次随机 add/del/lookup 混合对拍 0 mismatch**；
- MODE=0 回归由 `tb_mac_whitelist_seq` 承担：**8/8**，含 `cyc==18` 预算断言——顺序引擎在双模工程中不受集成改动影响。

### 7. L2 集成仿真

`tb_wl_integration` 双模扩展后 **7/7**：真实 `cpu_channel_tri` 链路下 SrcMAC 提取 → 触发查找 → 门控转发/丢弃全语义覆盖（加白放行 / 未命中拦截 / en·defpass 四象限 / 背靠背帧）；Test7 并发用例——数据面持续喂帧同时连续 add 触发 eviction 链，INV-C 窗口内 ≤2 帧 miss 后恢复命中，无死等 done、无挂死。

### 成果与后续

- **成果**：模式 2 布谷鸟哈希引擎 RTL 设计定稿，L1/L2 两级仿真全绿——L1 14/14（金模型 500 次随机对拍 0 mismatch、`cyc==2` 周期断言）、L2 集成 7/7（含 eviction 并发窗口用例）、MODE=0 回归 8/8；顺序（模式 0）与哈希（模式 2）双引擎在工程中共存、运行时可切。

### 二、工程任务明细（怎么干的）

#### 任务 1：P2 固件三个真实缺陷修复

**现象**：历史"空响应、板子越用越死（仅重载固件可救）"与代码行为长期对不上。

**怎么干的**：三方对账定位——管理面 pcap 抓包（发现 SYN-ACK **seq=0** 铁证：ISN 恒 0）+ JTAG 计数器交叉读 + RTL/固件源码核对。确认三缺陷：
1. `local_time_l`(0x07) 是"写 0x06 拍照"式锁存器，**全固件无人写 0x06** → 固件时钟恒 0 → 全部 TCP 定时器死转、TIME_WAIT/idle 永不过期、16 连接槽被僵尸占满后新 SYN 被静默丢弃；
2. TCP 定时常数按 50MHz 标定，JTAG 实测自由计数器 **1.035GHz**（错标 20.6×，且 32 位 4.15s 回卷）；
3. 收 FIN 后 FIN|ACK 从未上线 + LAST_ACK 对 final-ACK 精确匹配过苛 → 僵尸槽，PC 端口复用后新 SYN 被吞。

**修复**：`LCPU_LOCAL_TIME64()` 写 0x06 触发锁存后读 0x07/0x08 拼 64 位；常数按实测速率重标 + 计时数组改 uint64；FIN 路径改 RST|ACK 立即关闭。

**结果**：密度矩阵 2s/0.5s/0.1s 全绿；25 连接@0.2s 压力 **25/25**（旧固件必死场景）。commit `ef20dc8`。

**经验**：寄存器语义必须查 RTL，不能只看宏名；"板子坏了"的结论要用跨主端口证据（JTAG 走独立通路）验证。

#### 任务 2：P0 管理面"空响应/挂死"现象终审

**怎么干的**：三视角夹逼——固件内置取证计数器（弹包/解析/push，打包进 debug_rw_0/1/3）+ MAC 层收发计数（0x100/0x102）+ PC 侧 `iw station dump`（tx_failed），时间轴逐秒对齐。结果：真空期板卡只收得到广播（包首字字段逐包可见单播绝迹）、PC 成功交帧（tx_failed 零增量）→ **丢点在 AP 内部**（单播双向间歇死亡 10~45s 窗、~90s 周期，广播不受影响）。板卡硬件/RTL/固件三方清白。

**经验**：①"仅重载可救"实为重载时长（3~5min）盖过故障窗的误归因；②间歇性现象必须挂常驻观测器（jpoll/jwatch，已入仓 scripts/jtag/）而不是打一枪看一眼；③管理面走 WiFi 是本次全部噪音的来源。

**遗留**：队友 20 分钟有线验证终裁（路径在取证报告文内）；管理口长期应走有线。

#### 任务 3：P3 页面读迁移 sflash 寄存器路径

**怎么干的**：`web_pages.c` 全部字读撤离内存映射停等窗（原任一次停等=整机挂死且软件无法加超时），改走 `flash_cfg_read_word()`（带超时的 sflash 寄存器路径）；字节序以 TOC MAGIC 自校准（同配置区技巧），读超时降级为截断响应而非挂死。

**结果**：1077B 页面逐字节一致，21~29ms 有界延迟（原窗读 19ms）。commit `bfafd09`。

#### 任务 4：wl_status(0x301) 硬件驱动接入

**怎么干的**：寄存器原全工程无人驱动恒读 0（无法区分"正常/断线"，且是模式 2 验收第 1 项）。补 `mac_whitelist_seq` 输出 `wl_used_cnt`（cfg 域组合 popcount，无需 CDC）→ `mac_whitelist_top` 聚合 `{used_cnt, LOOKUP_MODE}` → wrapper 接入 reg_webserver 既有读 mux。

**结果**：上板证明 0x0（空表）→ 0x100（加一条）→ 0x0（删除）全循环，跨固件重载/跨 bit 重烧均正确。commit `7d3fee4`。模式 2 验收直接复用。

#### 任务 5：时序违例清零

**怎么干的**：先分拣再动手——v0008 基线 58 个违例端点分三类：①sgmii→c0 跨域被误当同步路径（Xilinx PCS/PMA 准静态配置信号）→ 补 false_path + async clock_groups；②`sfp_link_dbg/sfp_status_dbg` 36 位 GT 域状态位裸采进 50M 读寄存器（**真 CDC 缺口**）→ RTL 补逐位 2FF 同步器；③ILA 核寄存器总线（准静态，hub 一次访问跨整段 UART 传输）→ `set_max_delay -datapath_only 16ns` 封顶。约束与 RTL 一一对账后才落 XDC。

**结果**：WNS -5.93ns/58 端点 → **+0.797ns / 0 违例**，hold +0.021ns。commit `ccf732e`。

**经验**：长期存在的违例不等于可以接受——先分类（分析性违例 / 真 CDC 缺口 / 非功能路径），真的修、假的约束掉。

#### 任务 6：ILA 采样域匹配重构 + 抓取链路验证

**怎么干的**：核 6 初版把 50M 域信号挂 125M 采样钟（欠采样，波形不可信），按"采样时钟必须与探针信号同域"重构：核 6 = 50M CPU 域 7 探针、核 7 = 125M MAC 域 3 探针，NUM_CORES=6→8；repo 根 signals.json 同步 8 核布局；`ila_cap_tx.py` 支持 push/full 双触发模式。

**结果**：v0011 板端实测——武装 → **0.1s 触发命中** → 2048 样本回读 → 解码正常（102B 包 push、full 恒 0、waddr 静态块），全链路打通。

**经验**：抓不到波形先怀疑触发条件（本次触发押了"FIFO 满"假说，后被证伪），再怀疑仪器；false_path 只解决时序分析，不解决采样可信度。

#### 任务 7：构建脚本网络健壮化

**怎么干的**：`build_fpga.sh` 原每次构建在全新目录做 5 连 git 克隆，管理 WiFi 抖动下三次构建中途夭折（Network unreachable / SSH denied / `set -u` 未绑定变量各一次）。加本地 IP 缓存 `~/.cache/fpga_webserver_ip`：首次克隆后续离线可用，`IP_CACHE_REFRESH=1` 强刷；缓存种子用 v0010 构建目录的同源克隆（与已验证版本字节一致）。

**结果**：第四次构建全程缓存命中，直进综合。commit `ccf732e`。
